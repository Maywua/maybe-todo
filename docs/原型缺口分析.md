# maybe-todo 原型缺口分析

> 分析对象：`maybe-todo原型.md`（实体 1 个、页面 2 个、组件 1 个）
>
> 总体判断：骨架是清楚的——便签实体、首页列表、详情浮窗这条主线没问题，产品气质（轻、不催人、本地优先）也立得住。但它目前停在「界面清单」层面，真正决定实现的三个东西——**content 里存什么、什么时候落盘、删除到底删不删**——都还没定义。下面按「会卡住写代码的」→「做完才不别扭的」→「以后再补会后悔的」排序。
>
> 另有 4 条顺手记录的原型内部矛盾，建议先消掉（见第 1 节末尾）。

## 1. 会直接卡住开发的五个空洞（P0）

### 1.1 content 只有一句「对象类型，按类型不同」—— 最大的空洞

待办的 content 决定了：卡片缩略内容取什么、完成后怎么显示、怎么排序、怎么搜索、首页怎么统计「还有几件」。现在一个字段都没定。

至少要回答：

- 待办是「单条任务」还是「子项清单」？
- 完成状态存在哪一层？
- 有没有截止日期 / 提醒 / 优先级？

建议 v1（够用且好扩展）：

```jsonc
// type: "text"
{ "version": 1, "format": "plain", "text": "..." }

// type: "todo"
{
  "version": 1,
  "format": "checklist",
  "items": [
    { "id": "it_1", "text": "买牛奶", "done": true,  "doneAt": 1762312345678 },
    { "id": "it_2", "text": "顺路取快递", "done": false, "doneAt": null }
  ]
}
```

把 `version` 放进 content 是为了以后换格式（markdown、图片块、子任务嵌套）时能迁移，而不是在数据库里靠猜。

### 1.2 「保存逻辑待定」—— 但整个组件都挂在它上面

浮窗的显示内容里没有保存按钮，说明意图是自动保存；可又写了「新建模式下如果标题和内容都没输入，则不会保存」。这两句话之间有一整套没写的规则：

- 自动保存的触发点：输入防抖多久？失焦？关闭时 flush？程序退出时 flush？
- 新建的空便签什么时候真正落库？不落库就无法对它「锁定」或「删除」；落库又会积一堆「未命名」空便签。
- 关闭 = 保存，那**误改后想放弃**怎么办？没有任何取消路径。
- 保存失败（磁盘满、权限被拒、WebView 崩溃）怎么告知用户？现在没有任何错误反馈位。
- 只改标题或只改内容、甚至什么都没改，要不要更新 modified time？（直接影响按修改时间排序）

建议：输入防抖 500ms + 关闭/失焦立即 flush；新建时第一次输入才落库；删除给 Undo；保存失败用浮窗内的一条错误条而不是 alert。

### 1.3 删除语义自相矛盾：实体已经为回收站设计，回收站却「暂时不做」

`trashed time` 的定义写的是「已删除并进入回收站，同时也是判断是否该彻底删除的时间依据」，但页面清单里回收站是「暂时不做，留空」。这会导致三个都不好的结局，必须三选一：

| 方案 | 结果 |
| --- | --- |
| a. v1 硬删除 + 撤销 toast | 最简单，trashed time 字段先空着不实现 |
| b. v1 软删除 + 最简回收站页 | 和实体一致，多一个列表页的工作量（恢复 / 彻底删除 / 清空） |
| c. 软删除 + 没有入口 | 最差：用户看不见、恢复不了，还会被静默清理 |

配套还缺：「彻底删除」的**保留天数**没写；自动清理**在什么时候跑**没写（启动时？定时器？应用没开着就不清）；系统时间被用户改到过去会不会永久不清理。

建议选 b：回收站就三个操作（列表 / 恢复 / 彻底删除），保留 30 天，启动时清理一次并顺手清理孤儿附件。

### 1.4 列表顺序没有规则，实体也没有 order 字段

「便签列表：显示所有类型便签」——按什么排？如果按 modified time，正在编辑的便签会**实时跳到第一位**，编辑体验非常差（列表在用户眼皮底下动）。如果要手动拖拽排序，实体必须加 `order`。

建议：v1 按 `updatedAt` 倒序，`pinned`（置顶）留到 v2；如果确定 v1 要拖拽，现在就加 `order: number`（取相邻两条的中点，避免全表重排）。

### 1.5 平台与持久化没定，而它决定了整个交互

「退出：退出应用（仅桌面端）」暗示多端；README 里又写着 Capacitor 移动端规划、SQLite 是下一步、同步是第三步。但原型的 hover 菜单、浮窗、1.5s 启动页全是桌面交互——**触屏上没有 hover**。

建议明确：v1 = Tauri 桌面 + 浏览器预览；移动端只保证「能用」，所有 hover 菜单必须有点击/长按等价路径。持久化直接上 SQLite（实体字段的复杂度 localStorage 撑不住），localStorage 仅作浏览器预览的降级实现。

### 1.6 原型内部四处矛盾（先消掉）

1. 添加按钮「悬停时展开菜单」+「再次点击打开便签详情浮窗」：鼠标移到 + 上菜单已展开，这一次点击到底开菜单还是开浮窗？开哪种类型？
2. 新建模式**不显示功能菜单**，而功能菜单里有「锁定」——新便签想先锁定必须先保存一次再打开，这层限制是有意的吗？
3. 实体有 `trashed time`，回收站不做（见 1.3）。
4. `代办` 应为 `待办`；`created time` / `is locked` 带空格不能直接当 JSON key，文档和代码要有一份固定映射。

## 2. 实体层：缺的字段与格式问题

| 项 | 问题 | 建议 |
| --- | --- | --- |
| 时间格式 | `yy-mm-dd hh:mm:ss` 是**展示格式**，不能排序（两位年）、无时区、无毫秒；同一秒内的两条记录顺序不稳定；跨时区/夏令时算日期会错 | 内部存 Unix 毫秒（number），只在 UI 层格式化 |
| 待办完成态 | 实体没有完成字段。若塞进 content，首页统计「还有几件」要逐条解析 content | 加 `completedAt: number \| null`，由「全部子项完成」推导后持久化 |
| 排序 | 没有 `order` / `sortKey` | 视 1.4 的结论 |
| 版本 | 没有 `schemaVersion`，换格式时无从迁移 | 加，且和 content 内的 `version` 分开（一个管实体、一个管内容） |
| 标题长度 | 「0 到 30」按什么算？中文、emoji、组合字符、粘贴超长怎么办？超长是截断还是禁止输入？ | 30 个 grapheme，超出截断并给提示；存储层再校验一次 |
| 类型枚举 | 0/1 数字，将来加「清单 / 图片 / markdown」要改所有分支 | 字符串枚举 `"text" \| "todo"`，读到未知类型按 text 兜底 |
| 锁语义 | 只禁标题/内容编辑，那删除、拖拽、导出、回收站恢复呢？锁是 UI 标记**不是加密**，但名字容易被当成隐私保护；锁定时还有未保存内容怎么办？ | 明确定义为「只读」，列表卡片显示锁图标；切换锁定前先 flush 保存；不要暗示安全 |
| 命名 | 中文名 + 英文 key 混排（id / title / content / isLocked / trashedAt） | 文档保留中文名，JSON 用 camelCase，写一张字段映射表 |

建议一次补齐的最小集合：`schemaVersion`、`order`（若做拖拽）、`completedAt`、`pinned`（可选）、`color`（可选）、`lastOpenedAt`（可选，用于「最近」）。

## 3. 待办语义：一个 todo 应用最该写清的部分，原型里几乎是空的

这是最值得警惕的：**原型的菜单叫「新建待办」，但整个文档没有一行写待办长什么样、怎么算完成、完成后去哪。**

- 单条任务，还是子项清单？（「内容为对象」更像清单，但「新建待办」听起来像单条）
- 完成的定义：勾掉整条？还是勾完所有子项自动完成？部分完成怎么表示？
- 完成后显示在哪：列表里划线保留？折叠进「已完成」？自动消失？消失后还能找到吗？
- **卡片上能不能直接勾**：现在卡片整体点击是打开浮窗，如果勾选圈放在卡片上，两个点击目标会打架（尤其整张黄色字条都可点）。
- 截止日期 / 提醒：v1 做不做？不做就明确写「不做」——否则每次需求讨论都会反复。
- 过期 / 今天到期怎么显示（颜色、分组、图标）？
- 重复任务、优先级、标签：都不在实体里，明确放 v2/v3。
- **「maybe」的定位**：应用名叫 maybe，首页文案是「先记下来，再决定」。那需不需要一个「也许 / 以后再说」的状态或分类？如果需要，它和完成态是两套正交的状态，必须现在定，否则以后改动面很大。
- 待办的数量：首页「还有几件」的统计口径（按条还是按子项）。

建议 v1 待办最小集：单条文本 + 子项清单（可空）+ 整体完成态 + 完成时间；卡片上显示 `2/3` 进度；不做截止日期、提醒、重复、优先级，并在文档里写死「v1 不做」。

## 4. 交互与状态细节（做完才不别扭）

### 4.1 悬停菜单：触屏没有 hover，键盘够不到，指针移出还会误关

添加按钮和功能菜单都写「悬停时展开」。问题：触屏无法触发；键盘用户 Tab 不到菜单项；鼠标从按钮移向菜单项时若经过 1px 缝隙就关闭；多人共用触控板时误触。

建议：改成**点击切换**（点开、点外部/Esc 关闭），hover 只作为桌面增强；菜单项要能 Tab / 方向键；「+」按钮的菜单项是「新建笔记 / 新建待办」，点 + 本身不直接开浮窗，避免 1.6 的矛盾。

### 4.2 详情浮窗：模态还是浮窗？能不能多开？

「浮窗」在桌面便签应用里通常意味着非模态、可多开、可拖拽、位置记忆。但没写：背景列表能不能点、有没有遮罩、Esc 关不关、点外面关不关、多开时 z-index 怎么排、窗口最小尺寸下怎么响应。

建议 v1 单实例模态（遮罩、Esc 关闭、焦点陷阱、关闭后焦点回到原卡片），多开留 v2，但组件 API 现在就按「传 id、从 store 读」设计（见第 8 节），别把 title/content 当 props 传进来。

### 4.3 关闭 = 保存，但用户没有「放弃修改」的出口

自动保存下，误改一个字也保存了。至少：2 秒内的 Ctrl+Z 撤销、或浮窗底部一条「已保存 14:03」的轻提示，让用户知道发生了保存。

### 4.4 新建模式的两个具体漏洞

- 新建模式隐藏功能菜单 → 无法给新便签先「锁定」（见 1.6）。
- 现有代码里有一个全局单行快速输入（Ctrl+K），原型的首页却没有它。**这是产品方向冲突**：到底是要「快速收集箱」还是「便签墙 + 浮窗」？两套新建入口并存会让类型、焦点、快捷键规则变复杂，v1 建议只留一套。

### 4.5 占位菜单点了会发生什么

设置 / 回收站 / 关于「暂时不做，留空」：点进去是空白页、禁用项、还是 toast「敬请期待」？空白页是最差解。至少 disabled + 说明，或一行占位文案 + 返回首页。

### 4.6 列表与浮动的视觉状态一个都没定义

卡片 hover、按下、焦点环、拖拽中、锁定图标、待办完成、过期，一种都没写；长标题怎么截（30 字符封顶，但卡片宽度下可能一行放不下）、缩略内容取几行、待办没有文本时缩略区显示什么（`3/5 已完成`？）、空状态/加载态/数据损坏态，也都没有。

### 4.7 启动页

「最多显示 1.5s」——数据加载超过 1.5s 怎么办？300ms 就好了也要硬撑 1.5s 吗？能点击跳过吗？桌面端冷启动白屏与 splash 的衔接（Tauri 里应窗口 `visible: false`，等前端就绪再 show，否则先闪白屏再闪 splash）。

建议：等数据就绪，最长 1.5s（超时也进首页 + 骨架屏），最短 300ms 防闪烁，尊重 `prefers-reduced-motion`。

### 4.8 键盘与快捷键

现有 Ctrl+K 聚焦输入框。新结构下至少需要：新建、保存并关闭、Esc、删除、搜索、切换类型。原型没有快捷键表——桌面应用没有这个会被重度用户骂。

## 5. 页面与流程缺口

- **回收站**（见 1.3）：列表、恢复、彻底删除、清空、空状态、保留天数设置。
- **设置**：主题/深色、字号、语言、数据目录、导出/导入、回收站保留天数、启动行为、快捷键说明。原型说「暂时不做」，但主题和字号是 v1 就要落地的视觉变量，晚了要返工全站样式。
- **关于**：版本、许可、数据位置、反馈入口、检查更新。
- **搜索/筛选**：列表过 50 条就难用。v1 至少做「按类型筛选 + 关键词过滤」，全量搜索可以 v1.1。
- **首启与示例数据**：现在代码里塞了 2 条 seed 便签，正式版要么去掉，要么单独标记「示例」，否则会混进用户真实数据。
- **首页标题栏**：除了菜单和 +，是否显示应用名、条数、搜索框？现在什么都没有。

## 6. 数据生命周期与安全（本地优先应用最容易被忽略）

- **数据在哪**：SQLite 文件路径、怎么备份、换机怎么迁移。用户问「我的数据在哪」时要能一句话回答。
- **导出/导入**：JSON（可再导入）+ Markdown（人可读）。没有导出的本地应用，用户不敢存重要内容。
- **损坏恢复**：启动时 JSON/数据库解析失败**不要静默重置**。现在 `useNotes.ts` 里解析失败 `return seedNotes`，等于把用户数据替换成示例——这是真实的数据丢失路径。
- **配额**：SQLite 基本不用管；localStorage 预览要处理 `QuotaExceededError` 并明确提示。
- **崩溃恢复**：浮窗里未落盘的草稿，崩溃后能否恢复（写一个 draft 键即可）。
- **多窗口/多实例**：两个窗口同时写同一条，后写覆盖？需要按 `updatedAt` 做冲突检测或单窗口锁。
- **隐私**：锁定不是加密，数据明文落盘。需要在「关于」里写清楚，避免用户误以为锁住就安全。
- **卸载/清缓存**：README 现在自己承认「清缓存会丢，勿存重要内容」——这次发布前至少要给出导出按钮。

## 7. 可访问性、视觉、性能

- 图标按钮必须有 `aria-label`；浮窗要有焦点陷阱；菜单要有 `role="menu"` 和方向键支持；`+`/`☰` 不能只有图形没有文字标签。
- 黄底黑字的对比度要验（尤其缩略内容的浅灰）；深色模式下黄色字条的配色是另一套。
- 字号缩放（桌面 Ctrl +/-）、系统字体、中文标点。
- i18n：现在文案中英混杂（`v0.1.0 · 预览`、`Tauri 桌面端`），key 要抽出来，否则以后加英文版是重写。
- 性能：便签墙 500 / 2000 条时的渲染（虚拟滚动或分页）、搜索防抖、SQLite 分页；修改时间排序导致列表重排时不要整表重渲染。
- 动效：splash、浮窗出现/消失、reduced motion。

## 8. 与现有 v0.1 代码的落差（顺手记录）

- 当前 `Note = { id, text, done, createdAt }`，与原型实体（type / title / content / modifiedAt / trashedAt / isLocked）不是一套，需要一次数据迁移；建议在写新 UI 之前先把 SQLite schema 定下来。
- 当前 `App.tsx` 是营销落地页（大标题 + 卖点 + 状态卡），不是原型的「便签墙」首页；两者只能留一个作为启动后的默认页。
- `useNotes.add` 里 `slice(0, 200)`：**静默截断到 200 条**，用户完全无感知，数据会悄悄丢。上线前必须去掉，或改成「达到上限时禁止新增并提示」。
- `loadNotes` 解析失败返回 `seedNotes`：同第 6 节，等于把用户数据换成示例。
- localStorage 只适合浏览器预览；README 已把 SQLite 列为下一步，建议和 schema 定稿一起做，别先做 UI 再迁移。
- 现有 `Ctrl+K` 单行输入与「+ 选类型」是两套新建入口，需要统一（见 4.4）。
- `crypto.randomUUID()` 在 Tauri 自定义协议下可用，但浏览器旧版/非安全上下文不可用；已有兜底，保持即可。

## 10. 建议的 v1 范围（一页纸）

**做**：

- 启动页（可跳过、最长 1.5s、最短 300ms）
- 首页便签墙：按修改时间倒序、空状态、类型筛选、搜索过滤、`+` 点击展开新建菜单
- 详情浮窗：单实例、自动保存、Esc 关闭、焦点管理、删除带 Undo
